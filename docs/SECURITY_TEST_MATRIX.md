# Ынтымак — матрица проверок безопасности перед пилотом

Дата подготовки: 2026-11-15  
Ветка: `foundation/yntymak-0.9.1`

Этот документ описывает ожидаемое поведение схемы и подготовленных SQL-патчей. Он не является доказательством прохождения всех тестов: проверки с реальными пользователями и ролями должны быть выполнены на отдельной тестовой среде с синтетическими данными.

## Роли для тестовой среды

Создать отдельные тестовые аккаунты:
- обычный ученик без назначенных ролей;
- владелец проекта (создатель проекта);
- заявитель на вступление в чужой проект;
- председатель одного района;
- председатель другого района;
- представитель городского уровня;
- проверяющий полномочия;
- аккаунт без входа (anon).

Не использовать реальные аккаунты школьников и настоящие списки участников.

## Обязательные негативные тесты

1. Обычный ученик не может вставить запись в `role_assignments` или изменить назначенную себе роль.
2. Ученик не может читать чужие профили, заявки на роли или списки регистраций.
3. Прямая вставка/обновление/удаление `event_registrations` от имени `authenticated` запрещены; регистрация проходит только через `register_for_event()`.
4. Повторная регистрация на одно мероприятие и регистрация сверх лимита мест отклоняются.
5. Районный председатель не получает доступ к списку другого района.
6. Проверяющий не получает автоматически доступ к персональным спискам мероприятий.
7. Не-владелец проекта не может принять/отклонить заявку на вступление; пользователь может отозвать только собственную ожидающую заявку.
8. Ученик не может самостоятельно изменить `profiles.school_id`; ему доступны только поля отображаемого имени, языка и класса.
9. Даже проверяющий не может напрямую добавлять, менять или удалять `poll_options`; варианты создаются только атомарной RPC-функцией `create_community_poll()`.
10. Владелец проекта видит только заявки на собственные проекты; в интерфейсе заявки не раскрывают email или идентификатор аккаунта заявителя.
11. После принятия/отклонения заявки обновляется список именно того проекта, где была нажата кнопка.
12. Нельзя опубликовать непроверенный проект или предложение обходом серверной проверки.
13. Вызов RPC без сессии отклоняется.
14. Неавторизованные клиенты не могут вызывать SECURITY DEFINER функции.
15. Квота hosted AI атомарно ограничивает аккаунт десятью запросами за UTC-день; одиннадцатый запрос отклоняется.
16. Регистрация на мероприятие отображает агрегированное число участников, но не раскрывает их данные.
17. Предложение школьного уровня нельзя отправить, если школа не назначена профилю доверенным способом.
18. Истёкший опрос не отображается как открытый и не принимает голоса.
19. Назначение школы возможно только через `assign_profile_school()` подтверждённым представителем; действие записывается в закрытый журнал.
20. Нельзя напрямую читать таблицы `election_eligibility`, `election_voter_receipts`, `election_ballots` и `election_audit_log`.
21. Повторный вызов `cast_election_vote()` для того же аккаунта и выборов отклоняется, включая конкурентные запросы.
22. Недопущенный кандидат, недопущенный избиратель и голос вне временного окна отклоняются сервером.
23. Результаты недоступны на этапах `draft`, `nominations`, `review`, `campaign`, `voting` и `counting`; агрегированные итоги доступны только на этапах `objections` и `certified`.
24. Этапы выборов нельзя перескакивать или менять без подтверждённого представителя и причины.
25. Заявка кандидата использует имя из собственного профиля, а не произвольное имя из формы.
26. Нельзя открыть этап проверки до закрытия приёма заявок или голосование до окончания кампании и наступления времени старта.
27. Возражение может рассмотреть только подтверждённый представитель; решение и причина сохраняются в аудите.
28. Список допуска пустой или больше 5000 аккаунтов отклоняется; каждый аккаунт должен иметь профиль, а для школьного/районного уровня — подтверждённую школу нужной территории.
29. После закрытия выдвижения список допуска нельзя менять; представитель не может рассматривать собственную кандидатуру или собственное возражение.
30. Этап кампании нельзя начать без хотя бы одного одобренного кандидата.
31. Результаты недоступны на этапе `counting`; возражения принимаются только на этапе `objections`; сертификация блокируется при нерассмотренных возражениях.
32. Квитанция не содержит `ballot_id`, а бюллетень не содержит `user_id` или временной метки; приложение не предоставляет прямого способа сопоставить их.

33. Вошедший пользователь может обновить только имя, язык и класс своего профиля; попытка изменить school_id запрещена на уровне ACL.
34. В облачном интерфейсе школа и район недоступны для самостоятельного редактирования и отображаются только из подтверждённой связи.
35. Поле «О себе» не отправляется в Supabase, а локальные данные браузера хранятся в отдельном пространстве каждого аккаунта.
36. При переключении интерфейса на кыргызский профиль сохраняет язык ky, соответствующий ограничению схемы; значение kg не отправляется.
37. Очередь кандидатур доступна только подтверждённому представителю на этапе `review` и не возвращает ID пользователя/email.
38. Очередь возражений доступна только подтверждённому представителю на этапе `objections` и не раскрывает ID отправителя.
39. Этап кампании нельзя начать, пока остались ожидающие проверки кандидатур.
40. Подача публичной кандидатуры без обоих отдельных подтверждений публикации имени и программы отклоняется на сервере.
41. Публичный список кандидатов возвращает запись только при наличии обоих согласий и отметки времени согласия.
42. Приватная очередь модерации не раскрывает email или ID аккаунта кандидата; согласия фиксируются отдельными полями.
43. В демо-форме нельзя подать кандидатуру, пока не отмечены оба отдельных согласия на публикацию имени и программы.
44. Индексный патч добавляет семь заранее проверенных индексов для baseline foreign keys и не создаёт дубликатов существующих индексов.
45. Подтверждённый представитель может создать городское мероприятие и прочитать список только собственного события; для чужих событий нужно отдельное территориальное полномочие.
46. Облачная регистрация отклоняется без отдельного согласия на доступ организатора к данным именно этого события.
47. Имя участника берётся из профиля, школа — только из активного справочника школ, класс — из профиля; подмена этих значений параметрами клиента невозможна.
48. Список участников возвращает только записи с organizer_access_consent=true.
49. Районное мероприятие недоступно пользователю без подтверждённой школы в том же районе; городское мероприятие доступно с профилем без школьной привязки.
50. Повторная регистрация после статуса cancelled обновляет существующую запись, не создавая дубликат.
51. Профиль отклоняет пустое имя, строку из пробелов и имя короче двух символов после trim до записи в локальное или облачное хранилище.
52. При смене ID пользователя в Supabase Auth (включая событие из другой вкладки и внешний выход) приложение немедленно переключает локальный namespace, сбрасывает старый профиль/права и загружает профиль новой сессии; данные двух синтетических аккаунтов не смешиваются.
53. Все видимые даты в карточках и списках используют ru-RU для RU и ky-KG для KG, если браузер поддерживает эту локаль; иначе для KG используется нейтральный формат ДД.ММ.ГГГГ. Переключение языка не изменяет сохранённое значение даты.
54. В карточках статусы (review, open, in_progress, accepted, rejected, closed, draft, nominations, campaign, voting, cancelled, planning, team, active, completed) и территориальные уровни (school, district, city) отображаются на выбранном языке; неизвестные статусы не скрываются, а текущий пункт навигации в хлебных крошках использует тот же словарь RU/KY.
55. Если загрузка профиля аккаунта A завершается после переключения на аккаунт B (включая ошибочный ответ), результат A игнорируется: профиль, язык и локальное хранилище B остаются неизменными.
56. Уведомления о результатах действий и ошибках размещаются в области `role="status"`, `aria-live="polite"`, `aria-atomic="true"`; сообщение добавляется через `textContent` и не интерпретируется как HTML.
57. При открытии модального окна фокус переводится внутрь; Tab и Shift+Tab циклически перемещаются только по доступным элементам диалога; Escape/кнопка закрытия закрывают окно и возвращают фокус к инициатору либо к заголовку обновлённого раздела.
58. В форме профиля каждая подпись программно связана с соответствующим полем; форма имеет доступное имя, а подсказки для имени и поля «О себе» доступны через `aria-describedby` в обоих языках и в локальном/облачном режимах.
59. Формы входа и регистрации имеют отдельные доступные имена, подписи всех полей связаны через `for`/`id`, подсказки пароля и имени доступны через `aria-describedby` на RU/KY; имя регистрации после удаления пробелов проверяется в диапазоне 2–70 символов, а cloud signup повторяет проверки имени, пароля и языка до вызова Supabase Auth.
60. Клиентская форма входа требует непустой пароль, но не применяет HTML-ограничение `minlength`, предназначенное для новой регистрации; фактическая проверка пароля остаётся на стороне Supabase. Форма регистрации и `cloud signUp` продолжают требовать не менее 8 символов.

61. Формы создания предложения и проекта имеют доступное имя через `aria-labelledby`; каждое поле ввода, текстовая область и список выбора связано с видимой подписью через уникальные `for`/`id`. Проверить переход по всем полям клавиатурой и озвучивание подписей VoiceOver.

62. Облачная и локальная формы регистрации на мероприятие имеют доступное имя через `aria-labelledby`; в локальной форме подписи имени, школы и класса связаны с полями через уникальные `for`/`id`, а флажок согласия организатора в облачной форме имеет явную подпись-обёртку. Проверить клавиатурную навигацию и озвучивание VoiceOver в Safari на синтетическом мероприятии.
63. Полосы долей в карточках опросов являются декоративными и помечены `aria-hidden="true"`; название варианта и процент остаются доступным текстом. VoiceOver должен читать вариант и процент без отдельного объявления декоративной графики.
64. Форма учебной подачи кандидатуры имеет доступное имя через `aria-labelledby`; поля имени и программы связаны с подписями через `for`/`id`, а два отдельных обязательных согласия на публикацию сохранены. Проверить Tab и VoiceOver в Safari только на синтетической заявке; не использовать форму для официальных выборов.
65. Форма учебной подачи кандидатуры показывает подписи, пояснения и оба отдельных обязательных согласия на выбранном языке RU/KG. Проверить оба языка, доступное имя формы и сохранение demo-only предупреждения; не использовать реальные персональные данные и не включать официальные выборы.

## Текущие известные ограничения

- Школьные мероприятия пока заблокированы: таблице `events` ещё нужна проверенная связь со школой и подтверждённый школьный организатор.
- Подтверждённый представитель платформы может создавать городские мероприятия и видеть списки только собственных событий; городской/районный председатель — в пределах активного территориального полномочия.
- Роль `event_organizer` пока не даёт доступ к спискам участников: нужна отдельная привязка организатора к конкретному мероприятию.
- Городской и районный список участников содержит персональные данные; до реального пилота нужна утверждённая политика доступа, хранения и удаления данных.
- Модуль выборов подготовлен как техническая основа, но не включён. Создание выборов, список допуска и модерация кандидатов доступны только проверяющему представителю; заявки кандидатов используют имя из собственного профиля. Допуск избирателей должен утверждаться ответственным представителем; до реального пилота необходимы согласованное положение, тесты гонок/повторных голосов и независимый аудит.
- Для выборов добавлены серверные RPC создания, загрузки допуска, подачи/проверки кандидатур, переходов этапов, голосования, возражений и агрегированных результатов. Клиентские методы существуют, но `enableCloudElections=false`.
- Бюллетень не содержит `user_id`, а квитанция о голосовании хранится отдельно. Это разделение доступа, а не криптографическая гарантия анонимности: временные метки и доступ администраторов БД требуют дополнительной оценки; нельзя обещать абсолютную тайну голоса.
- Сообщения о травле, коррупции и другие чувствительные обращения не должны собираться до утверждения процедуры защиты детей, ответственных взрослых и конфиденциального доступа.
- Самостоятельное редактирование `profiles.school_id` запрещено; в текущей схеме поле остаётся `NULL`, пока не будет разработан и проверен отдельный процесс подтверждения школы.
- Варианты опроса защищены от прямых клиентских изменений; создание выполняется одной серверной функцией.
- Членство в проекте фиксируется серверной функцией после одобрения владельца; клиент получает только агрегированное число участников.
- Для hosted AI подготовлен отдельный патч квоты; его применение не включает функцию и не разрешает передачу пользовательских сообщений внешнему провайдеру.
- Счётчики регистрации мероприятий доступны только в агрегированном виде; клиент не получает список участников через эту RPC.
- Школьные предложения привязаны к подтверждённой школе профиля; районные и городские предложения доступны без заявления о школьной принадлежности.
- Модуль выборов использует отдельные таблицы eligibility, receipts и ballots; прямой доступ к списку избирателей, квитанциям и бюллетеням закрыт. Создание выборов и управление допуском доступны только проверяющему представителю.

## Состояние на момент подготовки

Новые изменения проверены SQL-транзакциями с `ROLLBACK`: проектная лаборатория вместе с RPC обработки заявок, новости/опросы вместе с блокировкой прямой записи вариантов, ограничения профиля, квота ИИ, назначение школы и фундамент выборов. `app.js` и `cloud.js` прошли синтаксическую проверку. Рабочая Supabase-схема не изменялась, облачные функции остаются выключенными. Эти проверки подтверждают синтаксис и отсутствие немедленной ошибки применения, но не заменяют интеграционные тесты с отдельными ролями.

66. Форма добавления новости имеет доступное имя через `aria-labelledby`; заголовок, текст, категория и дата связаны с видимыми подписями через `for`/`id`. Подписи, категории и действия переключаются между RU/KY, но значения категорий в данных остаются совместимыми с прежними русскими значениями; неизвестные категории не скрываются.

# Ынтымак 0.9.1 — расширенный прототип городской платформы школьного участия в Бишкеке

**Ынтымак** означает «единство, согласие». Эта сборка переосмысляет 0.8 как платформу школьных проектов, внутренней обратной связи, выборов ученического самоуправления, мероприятий и городского сотрудничества.

## Главное в 0.9.1

- Новая навигация и адаптивный интерфейс, тёмно-сине-бирюзовая палитра, орнаментальная эмблема и карточная структура.
- Главная панель с активностью, событиями и путём проекта.
- Внутренние предложения: школа / район / Бишкек, модерация и ответы. Юридические петиции и списки подписантов не создаются.
- Выборы: школьный, районный и городской уровни; бесплатная подача кандидатуры; статусы заявки; этапы выдвижения, кампании и голосования; демонстрационный голос.
- Проектная лаборатория: создание инициатив, заявки на вступление, одобрение владельцем, серверное членство и агрегированное число участников без раскрытия списка user_id.
- Мероприятия: открытая регистрация, лимит мест, агрегированный счётчик записавшихся и приватный список участников только для разрешённых ролей.
- Необязательные опросы мнения с агрегированным результатом.
- Новости и официальные источники, включая каталог Департамента образования мэрии Бишкека.
- Профиль: школа, район, класс и свободное поле «О себе / Моя деятельность». Написанная должность не даёт прав.
- Контекстный помощник «Ынтымак»: ученическое самоуправление, проекты, события, документы и четыре района Бишкека; готовые сценарии для повесток, выборов, предложений, RU/KG объявлений, бюджета и оценки проектов.
- Необязательное подключение внешней ИИ-модели через Supabase Edge Function. Ключ OpenAI никогда не помещается в браузер.
- Привилегированные роли проверяются сервером через `role_assignments` и `is_verification_representative()`; пользователь не может назначить роль себе через профиль.

## Важно понимать границы этой сборки

Это **расширенный браузерный прототип**, а не готовый государственный сервис или production-система.

- Без настройки Supabase формы, профили, предложения, команды, опросы и мероприятия работают в демо-режиме и хранятся в `localStorage` одного браузера. Они не передаются на другие устройства.
- Внешний ИИ по умолчанию выключен. Локальный помощник работает по тематическим сценариям. После отдельного подключения внешней модели поддерживается ограниченный контекст до шести предыдущих сообщений в текущей вкладке; контекст не сохраняется и фильтруется на стороне клиента и функции.
- Чтобы включить внешнюю модель, потребуется развернуть Edge Function и добавить API-ключ в Secrets на стороне Supabase. Запросы к модели могут тарифицироваться. Это должен делать взрослый владелец проекта; функция ограничивает вход по аккаунту и квоте.
- Локальное голосование не является тайным, не подтверждает личность и не годится для официальных выборов. Серверная схема, аудит и реальная процедура должны быть проверены до пилота.
- В демо-версии админ-панель доступна только при подтверждённой сервером роли. Нет пароля администратора, встроенного в код, и нет локального обхода.
- Регистрация участников и админ-списки в локальном браузере не защищены так, как облачная база с проверенными RLS-политиками. Используй только вымышленные тестовые данные.

## Запуск на Mac

1. Скачай `Yntymak_0_9_1.zip` и распакуй архив в «Загрузки».
2. Открой Terminal и выполни:

   ```bash
   cd ~/Downloads/Yntymak_0_9_1/yntymak-09 && python3 -m http.server 8006
   ```

3. Не закрывай Terminal. Открой Safari: `http://localhost:8006`.
4. Остановить сервер можно сочетанием `Control + C` в Terminal.
5. Чтобы проверить сохранение локального демо: создай тестовое предложение или проект, обнови страницу и проверь, остались ли данные.

Если ты распаковал архив в другое место, сначала открой папку `yntymak-09` в Finder, затем в Terminal введи `cd ` (с пробелом) и перетащи папку из Finder в окно Terminal; нажми Enter, затем запусти `python3 -m http.server 8006`.

> **Важно:** старые `supabase/schema_mvp07.sql` и `supabase/schema_mvp09.sql` относятся к прежней архитектуре с `platform_admins` / `is_platform_admin()` и не являются инструкцией для текущей ветки. Не запускай `schema_mvp07.sql` в рабочей базе. Для квоты ИИ подготовлен отдельный совместимый патч `supabase/patches/20261115_ai_quota.sql`.

## Состояние подключения Supabase и административных прав

Ветка содержит подготовленный клиентский слой и SQL-патчи для облачных функций, но это ещё не означает, что все функции развёрнуты в рабочей базе.

- Текущий Supabase-проект: `moy-shkolny-drug` (`suutpjjcendapzpebkcp`). Клиентская publishable-конфигурация в этой ветке намеренно оставлена пустой; ключи и пароли нельзя помещать в Git или отправлять в чат.
- Проверка административных полномочий использует существующую таблицу `role_assignments` и серверную функцию `is_verification_representative()`. Таблицы `platform_admins` и функции `is_platform_admin()` в текущей рабочей схеме нет.
- Роль проверяющего назначает только доверенный взрослый владелец проекта через контролируемую процедуру. Не назначай административные роли себе или другим ученикам.
- В `supabase-config.js` все облачные переключатели и внешний ИИ выключены. Не включай их, пока не выполнены миграции, проверка RLS и тесты с синтетическими аккаунтами.
- На момент аудита рабочая база содержит базовые таблицы профилей, школ, ролей и мероприятий; новые проектные, новостные и опросные таблицы из патчей ещё не развёрнуты. SQL-патчи проверяются в транзакциях `BEGIN … ROLLBACK`, без сохранения изменений в рабочей базе.
- Перед реальным включением владелец должен проверить email confirmation, включить защиту от утёкших паролей, настроить разрешённые Redirect URLs и пройти тесты из `docs/SECURITY_TEST_MATRIX.md`. Нужны резервная копия и журнал миграций; не запускай старые SQL-файлы повторно наугад.

**Профиль и школа:** пользователь может редактировать только отображаемое имя, язык и класс. Самостоятельная запись в `profiles.school_id` запрещается отдельным патчем; принадлежность к школе должна назначаться только после подтверждения взрослым координатором.

## Подготовленные SQL-патчи облачных функций

Патчи в `supabase/patches/` — это последовательные изменения схемы, а не автоматическая миграция. Перед применением сравни их с фактической схемой, сделай резервную копию и используй отдельную тестовую среду. Предлагаемый порядок и матрица проверок находятся в `docs/SECURITY_TEST_MATRIX.md`. Не применяй их к рабочей базе без одобрения взрослого владельца и независимой проверки.

## Включение внешней языковой модели (необязательно)

По умолчанию `enableHostedAI: false`. Локальный помощник остаётся доступен без внешней модели и без расходов.

Для подключения внешней модели нужен взрослый владелец Supabase-проекта:

1. Развернуть `supabase/functions/yntymak-assistant/index.ts` как Supabase Edge Function `yntymak-assistant`.
2. В Supabase Edge Function Secrets настроить `OPENAI_API_KEY` и `OPENAI_MODEL`. Модельный API может иметь стоимость; проверь доступные модели, цены, условия хранения и лимиты перед включением.
3. После отдельной проверки применить `supabase/patches/20261115_ai_quota.sql`, чтобы работала квота — максимум 10 вызовов на вошедший аккаунт в UTC-день.
4. Добавить секрет `APP_ALLOWED_ORIGINS` со списком точных origin через запятую (например, `http://localhost:8006` для теста; для опубликованного сайта — точный HTTPS-домен). Только после проверки функции установить `enableHostedAI: true` в `supabase-config.js`.
5. Проверить на синтетических сообщениях и просмотреть логи без сохранения пользовательских текстов.

Edge Function требует аутентифицированный Supabase JWT, ограничивает длину запроса, отсекает очевидные email/телефоны, использует Responses API с `store:false`, не сохраняет переписку в приложении и применяет школьные инструкции Бишкека. Это не гарантия полного удаления данных у провайдера. Поскольку внешняя модель может обрабатывать данные за пределами Кыргызстана, взрослый владелец/оператор до включения должен отдельно проверить статьи 79, 81, 82 и 89 Цифрового кодекса, основания обработки детских данных, согласия/представительство, трансграничную передачу, договор с обработчиком и постановление №384. До этой проверки оставь `enableHostedAI: false`. Не отправляй персональные/чувствительные сведения, даже когда функция подключена.

## Официальный контекст, используемый помощником

- Закон КР «Об образовании» №179 от 11 августа 2023 года, статья 22: основы самоуправления образовательных организаций и возможность создания советов обучающихся; конкретный порядок и компетенции определяются законодательством и уставом конкретной школы.
- Статья 39: права обучающихся, в том числе безопасная образовательная среда и защита от насилия и унижения достоинства.
- Официальный каталог образовательных организаций Департамента образования мэрии Бишкека: https://edu.e-meria.kg/schools . Конкретный школьный список не встроен в демо, чтобы не подменять реестр устаревшим или вымышленным списком.
- Закон КР «О порядке рассмотрения обращений граждан» №67: право на обращения и порядок официальной подачи регулируются отдельно; заявления и жалобы в интересах несовершеннолетних могут подаваться законными представителями. https://cbd.minjust.gov.kg/ . Ынтымак не является официальным порталом обращений.
- Требования к защите персональных данных при обработке в цифровых технологических системах утверждены постановлением Кабмина КР от 2 июня 2026 года №384; уровень защиты и обязанности оператора необходимо отдельно проверить со специалистом по действующим требованиям. https://cbd.minjust.gov.kg/230046833/edition/53878/ru . Помощник не выдаёт юридические заключения.

## Проверка качества ИИ-помощника

Используй набор сценариев `AI_TEST_CASES.md`. Он проверяет ответы о школьном самоуправлении, выборе района, каталоге школ, безопасных мероприятиях, проектах, двуязычных черновиках, приватности и реакциях на рискованные сообщения. Помощник не является RAG-системой с поиском по внутренним документам школы: он использует ограниченный статический контекст и источники, описанные в `AI_SYSTEM_PROMPT.md`.

## Известные ограничения

- CRUD для локальных сущностей в этом пакете — демонстрационный `localStorage`; SQL-модель из 0.7 не означает, что формы уже синхронизируются с Supabase.
- Внешний ИИ выключен по умолчанию. Без развертывания Edge Function отвечает локальный контекстный помощник.
- Каталог школ не зеркалируется в приложение автоматически.
- Кыргызская локализация частичная и требует проверки носителем языка/преподавателем.
- Официальный городской запуск невозможен без ответственного владельца, согласования со школами, проверки законодательства, правового основания для работы с данными несовершеннолетних, согласий/уведомлений, защиты и процедуры реагирования.


### Границы школьной персонализации

Помощник настроен на проверенную общегородскую справочную информацию и рабочие процессы ученического самоуправления Бишкека. Он не дообучен на данных отдельных школ, не имеет автоматического API-доступа к школьному каталогу и не знает внутренние уставы школ. Для персонализации по конкретной школе взрослый владелец проекта должен получить разрешённые публичные/официальные документы, проверить их актуальность, исключить персональные данные и только после этого добавить в отдельную базу знаний с источником и датой проверки. Пользовательский текст школы/района в профиле не считается проверенной принадлежностью.
